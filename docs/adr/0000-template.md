# ADR 0000: Short present-tense title of the decision

- **Status:** Proposed
- **Date:** YYYY-MM-DD
- **Deciders:** who agreed to this
- **Related:** issue / PR / ADR links

## Context

What forced a decision. State the constraints that were real at the time — the
platform, the gate, the incident, the cost — and the options that were genuinely
available. Cite concrete artifacts in the repository rather than describing them from
memory. A reader must be able to tell whether the constraint still holds.

## Decision

One sentence in the active voice: "We do X." Then the specifics — which files carry the
decision, which invariant is enforced where, and what is explicitly out of scope.

## Consequences

### What this buys

The benefits, stated plainly.

### What this costs

The downsides, stated just as plainly: the work it makes harder, the capability it gives
up, the failure mode it introduces, the maintenance it creates. An ADR with an empty
cost section is not finished.

### What would reverse it

The observation that would make this decision wrong — a traffic pattern, a platform
change, a budget breach, a version going EOL.
